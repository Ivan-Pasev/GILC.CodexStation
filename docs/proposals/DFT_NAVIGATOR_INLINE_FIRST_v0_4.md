# DFT Navigator Ω — Inline First (v0.4 candidate)

**Review status: PROPOSAL ONLY.** This document does not alter DFT 2.0 canon, CodexStation Ω101 constitutional authority, or the installed ChatGPT plugin.

## Decision
The default CodexStation/DFT interaction surface is the **ChatGPT answer itself**. Use the existing research evidence and Guided UNVEIL stages to answer substantively, then append **2–4 numbered, context-specific, one-click next actions**. The first action is the highest-value *admissible* step; the alternatives must be meaningfully different.

The former HexNav honeycomb visualization is kept as **Navigator Console**. Open that HUD only when the user explicitly invokes it. A request for `NEXT()`, an ordinary map or scientific question is not an implicit HUD request.

## Inline response format
**Unveiled:** strongest bounded finding and source/evidence status.

**Recommended:** 1 — execute the best admissible research step.

1. **NEXT · Advance frontier** — why this is the best current choice.
2. **UNVEIL · Deepen** — explore alternatives and source gaps.
3. **VERIFY · Challenge** — adversarial checks, proof/evidence.
4. **INTEGRATE · Prepare** — draft source artifact, with external mutations separately authorized.

Host-supported ChatGPT buttons send a new user turn and do not themselves certify tool execution. Text fallback: reply `1`, `2`, `1/3`, `1/2/3/4`. Composite actions run in user-declared order subject to budget, evidence, and effect gates; stale menus are rejected.

## Mobile
One-column, large-tap controls, clear numbers, no horizontal scrolling, no form, no full-screen HUD by default. The actual answer and citations remain visible independently of the action list.

## Kernel placement
`existing CodexStation root/source resolver -> Guided UNVEIL stages -> evidence/authority gates -> DFT Navigator read-only option planner -> host response renderer -> new user turn`.

Do not duplicate or replace the Guided UNVEIL SCOPE→SOURCES→UNVEIL→CHALLENGE→REFINE→DECIDE→RECEIPT state machine. The old DFT GPT predecessor supports honeycomb geometry but was not verified to specify this exact numeric menu convention. This inline rule is a newly formalized interaction contract.

## Boundaries
`UI_SELECTION != EXECUTION`, `RECOMMENDATION != AUTHORIZATION`, `SNAPSHOT != LIVE_CANON`, `SAME_LABEL != SAME_LINEAGE`, `FORMALIZABLE != PROVEN`, `SOURCE_REPORTED_PASS != LOCALLY_REPRODUCED_PASS`. An A2+ external effect requires observed host capability, explicit authorization, and a receipt. Numeric menu selection cannot close a science or plugin release gate.
